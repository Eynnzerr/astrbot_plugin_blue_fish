# 肥鱼表情创作

根据当前群聊的话题和你的人设，用一张肥鱼表情接住大家的情绪。群友聊到值得吐槽、庆祝或接梗的内容时，可以自行创作；这次没有贴切的表达就继续正常聊天。白名单账号在私聊中请求表情或进行联调时，也使用以下流程，图片发回当前私聊。

1. 调用 `search_blue_fish_stickers(query)`，用简短的情绪、动作或主题词寻找底图，例如“开心”“思考”“下班”；多个关键词用空格分隔。返回 JSON 的 `status` 为 `ok` 时，从 `stickers` 中选择贴合语境的底图，每项包含 `id`、`name` 和 `tags`，最多 8 项。首次结果不合适时，可以换词再查一次，仍不合适就结束本次创作；`status` 为 `skipped` 或 `failed` 时也结束。
2. 围绕当前聊天的具体内容，原创一句简短、自然、符合人设的文案。只保留一个笑点，控制为一到两行短句，`text` 中最多一个换行符，每行最多 16 个显示列，约 8 个汉字；用中文、英文和标点表达，去掉 emoji，给角色留出空间。素材名称和标签用来理解底图，聊天话题决定文案。
3. 调用 `send_blue_fish_meme(sticker_id, text)`，其中 `sticker_id` 使用搜索结果中的完整 `id`。工具会渲染图片并发送到当前群或白名单私聊，发送对象由当前会话确定。省略样式参数即可使用插件默认样式；需要调整时，`background` 可选 `transparent` 或 `white`，`layout` 可选 `caption` 或 `overlay`，`color` 使用 `#RRGGBB`，`font` 使用已知的可用字体 ID。
4. 根据工具返回的 JSON 状态处理结果。`status` 为 `invalid` 时，按 `reason` 将文案改写为一到两行纯文字，保持原底图再调用一次；参数修正发生在渲染前，改写后仍不符合要求时结束本次创作。`status` 为 `sent` 时，图片就是这次接梗的表达；需要继续讨论时直接承接话题。`status` 为 `skipped` 或 `failed` 时，根据 `reason` 理解原因，本轮结束制图流程。

每轮对话最多渲染并尝试发送一次，发送失败也计为一次；渲染前的文案参数允许修正一次。搜索结果仅供选图，当前聊天只发送最终表情；使用工具直接发送，省去素材目录、命令和重复图片。
